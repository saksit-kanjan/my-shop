# ออกแบบระบบ POS หน้าร้านและระบบหลังร้าน

Nov 6, 2026 · @Saksit Kanjan

## ขอบเขตและสมมติฐาน

ระบบมี 2 ส่วน คือ POS สำหรับขายหน้าร้าน และระบบหลังบ้านสำหรับจัดการหน้าร้าน ทั้งสองทำงานบนเซิร์ฟเวอร์ on-prem ใน LAN ของร้าน ใช้ฐานข้อมูลชุดเดียว รองรับ POS 1–5 เครื่อง และไม่ต้องใช้ internet ถ้ามีหลายสาขา แต่ละสาขาติดตั้งแยกและทำงานอิสระ

**อยู่ในขอบเขต (เฟสแรก)**

- ขายหน้าร้าน รับชำระเงิน ยกเลิกบิล คืนสินค้า
- กะและเงินสด
- สินค้า ราคา สต็อก การรับสินค้าและตรวจนับ
- สมาชิก แต้ม โปรโมชัน
- ใบเสร็จและใบกำกับภาษี
- รายงาน ผู้ใช้และสิทธิ์ audit log

**นอกขอบเขต (ทำทีหลัง)**

- เชื่อมเครื่องพิมพ์ใบเสร็จ ลิ้นชักเงิน และเครื่องรูดบัตรโดยตรง (ระบบออกแบบให้เสียบเพิ่มได้)
- ระบบส่วนกลางระหว่างสาขา การยืนยันยอดอัตโนมัติจากธนาคาร ขายออนไลน์ และ e-Tax Invoice

**สมมติฐาน**

- เป็นร้านค้าปลีกทั่วไป ไม่ใช่ร้านอาหาร จึงไม่มีโต๊ะ ครัว หรือ modifier
- ร้านจดทะเบียน VAT และราคาที่แสดงเป็นราคารวม VAT 7%
- สกุลเงินเดียวคือบาท ปัดเศษถึงทศนิยม 2 ตำแหน่ง

## ผู้ใช้งานและสิทธิ์

ระบบมี 4 บทบาทหลัก สิทธิ์ผูกกับบทบาท ไม่ผูกกับตัวคน และเจ้าของปรับสิทธิ์รายข้อได้ แคชเชียร์เข้า POS ด้วยรหัสพนักงานและ PIN ส่วนหลังร้านใช้ username และรหัสผ่าน

| สิทธิ์ | แคชเชียร์ | หัวหน้ากะ | ผู้จัดการ | เจ้าของ |
| --- | --- | --- | --- | --- |
| ขาย รับชำระ พักบิล | ✓ | ✓ | ✓ | ✓ |
| ลบรายการก่อนปิดบิล | ✓ | ✓ | ✓ | ✓ |
| ส่วนลดเกินเพดานที่กำหนด | ขออนุมัติ | ✓ | ✓ | ✓ |
| ยกเลิกบิลที่ปิดแล้ว (void) | ขออนุมัติ | ✓ | ✓ | ✓ |
| คืนสินค้า | ขออนุมัติ | ✓ | ✓ | ✓ |
| เปิดลิ้นชักโดยไม่มีการขาย | – | ✓ | ✓ | ✓ |
| เปิดและปิดกะ | ✓ | ✓ | ✓ | ✓ |
| ดูยอดที่ระบบคาดไว้ตอนปิดกะ | – | ✓ | ✓ | ✓ |
| จัดการสินค้าและราคา | – | – | ✓ | ✓ |
| รับสินค้า ปรับสต็อก ตรวจนับ | – | ดูอย่างเดียว | ✓ | ✓ |
| จัดการโปรโมชันและสมาชิก | – | – | ✓ | ✓ |
| ดูรายงานยอดขาย | – | กะของตัวเอง | ✓ | ✓ |
| ดูต้นทุนและกำไร | – | – | – | ✓ |
| จัดการผู้ใช้และสิทธิ์ ตั้งค่าร้าน | – | – | – | ✓ |

**การขออนุมัติ:** เมื่อแคชเชียร์ทำรายการที่ต้องอนุมัติ ผู้มีสิทธิ์ใส่ PIN ที่เครื่องนั้นได้เลย ระบบบันทึกทั้งผู้ขอและผู้อนุมัติไว้ใน audit log

**นับเงินแบบไม่เห็นยอด:** แคชเชียร์นับเงินตอนปิดกะโดยไม่เห็นยอดที่ระบบคาดไว้ (blind count) เพื่อให้ผลต่างที่บันทึกตรงกับความจริง

## ภาพรวมโมดูล

หน้าร้านเขียนข้อมูลการขาย เงิน และกะ ส่วนหลังร้านดูแลข้อมูลหลักและการตั้งค่า ทั้งสองฝั่งอ่านและเขียนฐานข้อมูลกลางชุดเดียวกัน ข้อมูลจึงตรงกันทันทีโดยไม่ต้อง sync

## บริการพื้นฐานที่ใช้ร่วมกัน

กฎที่กระทบตัวเลขเงิน สต็อก และเอกสาร ต้องเขียนไว้ที่เดียวแล้วให้ทั้งสองระบบเรียกใช้ เพื่อให้ POS กับหลังบ้านคำนวณได้ผลตรงกันเสมอ

| บริการ | หน้าที่ | ใช้โดย |
| --- | --- | --- |
| ยืนยันตัวตนและสิทธิ์ | ตรวจ PIN และรหัสผ่าน บทบาท การขออนุมัติ | POS หลังบ้าน |
| คำนวณราคาและภาษี | ราคา ส่วนลด ถอด VAT ปัดเศษ ด้วยกฎชุดเดียว | POS หลังบ้าน |
| Promotion engine | หาโปรที่เข้าเงื่อนไขและคิดส่วนลดของตะกร้า | POS (หลังบ้านใช้ทดลองโปรก่อนเปิดใช้) |
| ออกเลขเอกสาร | ออกเลขต่อเนื่องไม่มีช่องว่างต่อประเภทและเครื่อง | POS หลังบ้าน |
| Stock ledger | บันทึกการเคลื่อนไหวและคำนวณยอดคงเหลือกับต้นทุนเฉลี่ย | POS (ขาย คืน) หลังบ้าน (รับ ปรับ ตรวจนับ) |
| Points ledger | บันทึกการได้ ใช้ คืน และหมดอายุของแต้ม | POS หลังบ้าน |
| สร้างใบเสร็จ | สร้างข้อมูลใบเสร็จกลางที่ไม่ผูกกับรูปแบบการพิมพ์ | POS หลังบ้าน (พิมพ์ซ้ำ ใบเต็มรูป) |
| Event และงานเบื้องหลัง | ส่ง event ปิดบิล ปิดกะ ให้โมดูลเสริมและงานที่ไม่ต้องรอ | ทั้งระบบ |
| Audit log | บันทึกการกระทำที่ต้องตรวจสอบ | ทั้งระบบ |
| นาฬิกาและวันทำการ | เวลาอ้างอิงจากเซิร์ฟเวอร์ และการตัดวันทำการ | ทั้งระบบ |
| Backup อัตโนมัติ | สำรองข้อมูลทุกวันและเก็บย้อนหลัง | ทั้งระบบ |

## Flow การขายหน้าร้าน

&#91;embedded content: flow การขาย · 5 ขั้น 1 จุดตัดสินใจ\]

บิลที่ยังไม่ปิดเป็นแค่ตะกร้าที่แก้ได้อิสระ ทุกอย่างที่กระทบเงิน สต็อก และเอกสารภาษีเกิดตอนปิดบิลครั้งเดียว

- **ตะกร้า:** สแกนซ้ำเพิ่มจำนวน แก้จำนวนหรือลบรายการได้ สินค้าที่หาไม่เจอในระบบใช้ SKU ราคาเปิดแทน
- **โปรโมชัน:** คำนวณใหม่ทุกครั้งที่ตะกร้าเปลี่ยน และแสดงส่วนลดที่ได้ให้แคชเชียร์เห็นทันที
- **พักบิล:** เก็บตะกร้าไว้แล้วเริ่มบิลใหม่ เรียกคืนได้จากเครื่องเดิมภายในกะเดิม บิลพักที่ค้างอยู่ตอนปิดกะต้องเคลียร์ก่อน
- **ยกเลิกก่อนชำระ:** ทิ้งตะกร้าได้เลย ไม่เกิดเอกสาร แต่บันทึกไว้ใน audit log
- **ปิดบิล:** ถ้าขั้นใดล้มเหลว ระบบยกเลิกทั้งหมด ตะกร้าและการชำระยังอยู่ครบให้ลองใหม่

## การชำระเงิน

บิลหนึ่งใบรับชำระได้หลายรายการ (แยกจ่าย) และปิดบิลได้เมื่อยอดรับครบเท่ายอดสุทธิพอดี ส่วนที่เกินจากเงินสดคือเงินทอน

| ช่องทาง | สิ่งที่แคชเชียร์ทำ | ข้อมูลที่บันทึก | ทอนได้ |
| --- | --- | --- | --- |
| เงินสด | กรอกยอดที่รับ หรือกดปุ่มธนบัตรลัด | ยอดรับ เงินทอน | ได้ |
| PromptPay QR | ระบบแสดง QR ระบุยอด ลูกค้าสแกนจ่าย แคชเชียร์ตรวจยอดเข้าจากแจ้งเตือนหรือแอปธนาคารแล้วกดยืนยัน | ยอด เวลา เลขอ้างอิงธนาคาร (ถ้ามี) และผู้ยืนยัน | ไม่ได้ |
| บัตร (รูดเครื่อง EDC แยก) | รูดที่เครื่องธนาคาร แล้วกรอก approval code | ยอด approval code 4 หลักท้ายบัตร ประเภทบัตร | ไม่ได้ |
| โอนเงิน | ตรวจสลิปแล้วกดยืนยัน | ยอด เวลา เลขอ้างอิง | ไม่ได้ |
| แต้มสมาชิก | เลือกใช้แต้มเป็นส่วนลด | จำนวนแต้ม มูลค่า | ไม่ได้ |
| บัตรกำนัล / คูปองมูลค่า | สแกนหรือกรอกรหัส | รหัส มูลค่าที่ใช้ | ไม่ได้ |

**กฎ**

- ช่องทางที่ไม่ใช่เงินสดรับได้ไม่เกินยอดคงค้าง ป้องกันการทอนเงินสดจากการจ่ายบัตรหรือโอน
- ถ้ามีหลายช่องทางและมีเงินสดปน ให้คิดเงินสดเป็นรายการสุดท้าย เพื่อให้เงินทอนคำนวณจากยอดคงค้างจริง
- ลบรายการชำระที่ยังไม่ปิดบิลได้ หลังปิดบิลแล้วต้องทำผ่านการยกเลิกหรือคืนสินค้าเท่านั้น
- ร้านเปิดหรือปิดช่องทางชำระแต่ละแบบได้จากหลังร้าน
- การปัดเศษสตางค์ (ถ้าร้านใช้) ทำเฉพาะยอดเงินสด และบันทึกส่วนต่างเป็นรายการปัดเศษแยกไว้

## ยกเลิกบิล คืนสินค้า เปลี่ยนสินค้า

บิลที่ปิดแล้วไม่ถูกแก้หรือลบเลย ทุกการกลับรายการคือเอกสารใหม่ที่อ้างอิงบิลเดิม พร้อมเหตุผลและผู้อนุมัติ

| กรณี | ใช้เมื่อ | ผลกับเงิน | ผลกับสต็อก | เอกสาร |
| --- | --- | --- | --- | --- |
| ลบรายการ | ก่อนปิดบิล | – | – | ไม่มี (บันทึกใน audit log) |
| ยกเลิกบิล (void) | ภายในกะเดียวกันกับที่ขาย และยังไม่ปิดกะ | คืนเต็มจำนวนตามช่องทางเดิม | คืนเข้าสต็อกทั้งหมด | บิลเดิมสถานะ "ยกเลิก" และพิมพ์ใบยกเลิก |
| คืนสินค้า (refund) | หลังปิดกะ หรือคืนบางรายการ | คืนตามสัดส่วนที่จ่ายจริง | คืนเข้าสต็อก หรือตัดเป็นของเสีย | ใบลดหนี้ อ้างอิงบิลเดิม |
| เปลี่ยนสินค้า | คืนชิ้นเดิมแล้วซื้อชิ้นใหม่ | ลูกค้าจ่ายหรือรับส่วนต่าง | รับคืนชิ้นเดิม ตัดชิ้นใหม่ | ใบลดหนี้ และบิลขายใหม่ ผูกกันไว้ |

**กฎ**

- คืนได้ไม่เกินจำนวนที่ขายในบิลเดิม หักด้วยที่คืนไปแล้ว
- ยอดคืนคิดจากราคาหลังส่วนลดที่ลูกค้าจ่ายจริง ส่วนลดระดับบิลกระจายตามสัดส่วนของแต่ละรายการ
- ถ้าการคืนทำให้บิลไม่ผ่านเงื่อนไขโปรโมชันเดิม (เช่น ซื้อ 2 แถม 1) ให้หักมูลค่าของแถมออกจากยอดคืน
- แต้มที่ได้จากบิลเดิมถูกดึงคืนตามสัดส่วน และแต้มที่ลูกค้าใช้ไปถูกคืนเข้าบัญชี
- การคืนเงินช่องทางบัตรหรือโอนบันทึกในระบบว่าคืนผ่านช่องทางไหน แต่ขั้นตอนจริงทำนอกระบบ
- กำหนดระยะเวลาคืนสินค้าได้ (เช่น 7 วัน) เกินกำหนดต้องให้ผู้จัดการอนุมัติ

## กะและการจัดการเงินสด

ทุกบิลต้องอยู่ในกะ หนึ่งเครื่อง POS มีกะเปิดอยู่ได้ทีละกะ และกะหนึ่งผูกกับแคชเชียร์ผู้รับผิดชอบลิ้นชักหนึ่งคน

1. **เปิดกะ:** แคชเชียร์เข้าระบบ แล้วนับเงินทอนตั้งต้น (float) แยกตามชนิดธนบัตรและเหรียญ
2. **ระหว่างกะ:** ขายตามปกติ และบันทึกเงินเข้าออกที่ไม่ใช่การขายพร้อมเหตุผลทุกครั้ง
   - **นำเงินออก (cash drop):** ย้ายเงินส่วนเกินเข้าตู้เซฟ ลดความเสี่ยง
   - **จ่ายเงินออก (paid out):** เช่น ค่าน้ำแข็ง ค่าส่งของ
   - **นำเงินเข้า (paid in):** เช่น เติมเงินทอน
3. **X report:** ดูสรุปยอดกะปัจจุบันได้ทุกเมื่อโดยไม่ปิดกะ
4. **ปิดกะ:** แคชเชียร์นับเงินจริงแบบ blind count ระบบคำนวณผลต่าง (ขาดหรือเกิน) ส่วนช่องทางอื่นแสดงยอดให้กระทบกับสลิป EDC และแอปธนาคาร
5. **Z report:** สรุปปิดกะ แล้วล็อกกะ ห้ามขายหรือยกเลิกบิลในกะนั้นอีก
6. **ปิดวัน:** หลังทุกกะในวันปิดครบ ผู้จัดการปิดวันเพื่อตัดยอดรายวันสำหรับรายงานและบัญชี

**ยอดเงินสดที่ควรมี** = เงินตั้งต้น + ขายด้วยเงินสด − เงินทอน − คืนเงินสด + นำเงินเข้า − จ่ายเงินออก − นำเงินออก

**Z report ประกอบด้วย:** ยอดขายรวมและสุทธิ ส่วนลด VAT จำนวนบิล ยอดยกเลิกและคืนสินค้า ยอดแยกตามช่องทางชำระ รายการเงินเข้าออก เงินที่ควรมี เงินที่นับได้ และผลต่าง

**ผลต่างเกินเกณฑ์** (เช่น เกิน 100 บาท) ต้องให้หัวหน้ากะใส่ PIN รับทราบ และกรอกหมายเหตุก่อนปิดกะได้

## สินค้าและราคา

หน่วยที่ขายและตัดสต็อกจริงคือ SKU ส่วนสินค้า (product) เป็นแค่กลุ่มที่รวม SKU หลายตัวไว้ เช่น เสื้อรุ่น A มี SKU แยกตามสีและไซส์

**โครงสร้างสินค้า**

- **หมวดหมู่:** ซ้อนกันได้ 2–3 ระดับ ใช้จัดหน้าจอ POS และแยกรายงาน
- **สินค้า:** ชื่อ หมวด ยี่ห้อ รูป สถานะขาย/หยุดขาย ประเภทภาษี (VAT หรือยกเว้น VAT)
- **SKU:** รหัส SKU ตัวเลือก (สี ไซส์) ราคาขาย ต้นทุน และบาร์โค้ดหลายตัวต่อหนึ่ง SKU ได้
- **หน่วยนับและหน่วยขาย:** เช่น ขายเป็นชิ้นหรือแพ็ก 6 ชิ้น แต่ละหน่วยมีบาร์โค้ดและราคาของตัวเอง โดยตัดสต็อกเป็นหน่วยฐานเสมอ
- **สินค้าชั่งน้ำหนัก:** ราคาต่อกิโลกรัม รองรับบาร์โค้ดจากเครื่องชั่งที่ฝังน้ำหนักหรือราคา (ทำเป็นโมดูลเสริมได้)
- **สินค้าชุด (bundle):** ขายเป็นหนึ่งรายการในราคาชุด แต่ตัดสต็อกแยกเป็นชิ้นส่วนประกอบ
- **สินค้าไม่ตัดสต็อก:** เช่น ค่าบริการ ค่าห่อของขวัญ

**ราคา**

- ราคาขายเก็บเป็นราคารวม VAT ระบบถอด VAT ออกตอนออกเอกสาร
- ราคาสมาชิกแยกจากราคาปกติได้
- แคชเชียร์แก้ราคาหน้าร้านได้เฉพาะ SKU ที่เปิดสิทธิ์ "ราคาเปิด" ไว้ (เช่น สินค้าทั่วไปไม่มีบาร์โค้ด)
- การเปลี่ยนราคามีวันเริ่มมีผล และเก็บประวัติราคาไว้ทุกครั้ง

**ต้นทุน:** ใช้ต้นทุนถัวเฉลี่ยถ่วงน้ำหนัก (moving average) คำนวณใหม่ทุกครั้งที่รับสินค้า และ snapshot ต้นทุน ณ เวลาขายไว้ในรายการขายเพื่อใช้คิดกำไร

## สต็อก

ยอดคงเหลือของแต่ละ SKU คือผลรวมของรายการเคลื่อนไหวทั้งหมด (stock ledger) ไม่มีการแก้ตัวเลขคงเหลือตรง ๆ ทุกการเปลี่ยนแปลงต้องมีเอกสารต้นทาง

| ประเภทการเคลื่อนไหว | เอกสารต้นทาง | ทิศทาง | ใครทำ |
| --- | --- | --- | --- |
| รับสินค้า | ใบรับสินค้า (อ้างอิงใบสั่งซื้อได้) | เข้า | ผู้จัดการ |
| คืนสินค้าให้ผู้ขาย | ใบคืนผู้ขาย | ออก | ผู้จัดการ |
| ขาย | บิลขาย | ออก | อัตโนมัติ |
| ยกเลิกบิล / ลูกค้าคืน | ใบยกเลิก / ใบลดหนี้ | เข้า | อัตโนมัติ |
| ตัดของเสีย หาย หมดอายุ | ใบปรับสต็อก พร้อมเหตุผล | ออก | ผู้จัดการ |
| ปรับจากการตรวจนับ | ใบตรวจนับ | เข้าหรือออก | ผู้จัดการ |

**รับสินค้า:** เลือกผู้ขาย สแกนหรือเลือก SKU กรอกจำนวนและต้นทุนต่อหน่วย ระบบบันทึกยอดเข้าและคำนวณต้นทุนเฉลี่ยใหม่ ถ้ามีใบสั่งซื้อ ระบบเทียบจำนวนที่รับกับที่สั่งและเก็บยอดค้างรับไว้

**ตรวจนับสต็อก**

1. ผู้จัดการสร้างรอบตรวจนับ เลือกทั้งร้านหรือบางหมวด
2. ระบบถ่ายภาพยอดในระบบ ณ เวลาเริ่มไว้ (snapshot)
3. พนักงานสแกนนับจริง นับซ้ำได้และระบบรวมยอดให้
4. ระบบแสดงผลต่างระหว่างยอดนับกับ snapshot บวกการขายระหว่างนับ
5. ผู้จัดการอนุมัติ แล้วระบบสร้างรายการปรับสต็อกอัตโนมัติ

**กฎ**

- ตั้งค่าได้ว่าจะยอมขายติดลบหรือไม่ แนะนำให้ยอมแต่แจ้งเตือน เพราะสินค้าอยู่หน้าร้านจริงแต่ยังไม่ได้รับเข้าระบบเป็นเรื่องที่เกิดบ่อย
- ตั้งจุดสั่งซื้อซ้ำ (reorder point) ต่อ SKU ระบบแสดงรายการสินค้าใกล้หมด
- ติดตาม lot และวันหมดอายุเป็นตัวเลือกต่อ SKU สำหรับสินค้าที่ต้องการเท่านั้น

## สมาชิก แต้ม และโปรโมชัน

สมาชิกระบุตัวด้วยเบอร์โทร แต้มเก็บเป็น ledger แบบเดียวกับสต็อก และโปรโมชันคำนวณโดย engine กลางที่ POS เรียกทุกครั้งที่ตะกร้าเปลี่ยน

**สมาชิก**

- ข้อมูล: ชื่อ เบอร์โทร วันเกิด (ไม่บังคับ) ระดับสมาชิก วันสมัคร
- สมัครที่ POS ได้ทันทีด้วยเบอร์โทร ขอความยินยอมการเก็บข้อมูลตาม PDPA และบันทึกเวลาที่ยินยอม
- ผูกสมาชิกกับบิลก่อนชำระเงิน เพื่อให้ได้ราคาสมาชิกและแต้ม
- ข้อมูลภาษีสำหรับออกใบกำกับเต็มรูป (ชื่อ ที่อยู่ เลขผู้เสียภาษี สาขา) เก็บแยกไว้ในสมาชิกได้

**แต้ม**

- ได้แต้มตามยอดสุทธิหลังส่วนลด เช่น 25 บาท = 1 แต้ม ปัดเศษลง
- ใช้แต้มแทนเงินตามอัตราที่ตั้ง เช่น 100 แต้ม = 10 บาท
- แต้มมีวันหมดอายุได้ (เช่น สิ้นปีถัดไป)
- ทุกการได้ ใช้ คืน หรือหมดอายุของแต้มเป็นหนึ่งรายการใน ledger

**ประเภทโปรโมชัน**

| ประเภท | ตัวอย่าง |
| --- | --- |
| ลดราคาต่อรายการ | SKU นี้ลด 20% หรือลด 50 บาท |
| ซื้อ X แถม Y | ซื้อ 2 แถม 1 หรือซื้อ A แถม B |
| ราคาพิเศษเมื่อซื้อจำนวน | 3 ชิ้น 100 บาท |
| ส่วนลดท้ายบิล | ซื้อครบ 1,000 บาท ลด 100 บาท |
| คูปองส่วนลด | กรอกรหัสที่ POS ใช้ได้ครั้งเดียวหรือหลายครั้ง |
| เฉพาะสมาชิก | ส่วนลดเพิ่มสำหรับสมาชิกระดับ Gold |

**กฎของ engine**

- โปรโมชันทุกตัวมีช่วงวันเวลา วันในสัปดาห์ ขอบเขตสินค้าหรือหมวด และลำดับความสำคัญ
- ค่าเริ่มต้นคือโปรโมชันระดับรายการไม่ซ้อนกัน ระบบเลือกตัวที่ลูกค้าได้ประโยชน์มากที่สุด ส่วนลดท้ายบิลคิดหลังส่วนลดรายการ
- ตั้งได้ว่าโปรตัวใดซ้อนกับตัวอื่นได้
- ใบเสร็จแสดงชื่อโปรโมชันและยอดส่วนลดทุกรายการ
- ส่วนลดแบบ manual จากแคชเชียร์ ใช้ได้ตามเพดานของบทบาท

## เอกสารและใบเสร็จ

ทุกบิลขายออกใบกำกับภาษีอย่างย่อเป็นค่าเริ่มต้น และออกใบกำกับภาษีเต็มรูปเพิ่มได้เมื่อลูกค้าขอ เลขเอกสารแต่ละประเภทรันต่อเนื่องไม่มีช่องว่าง

| เอกสาร | ออกเมื่อ | เลขเอกสาร |
| --- | --- | --- |
| ใบกำกับภาษีอย่างย่อ / ใบเสร็จ | ปิดบิลขาย | รันแยกต่อเครื่อง POS เช่น `T01-2611-000123` |
| ใบกำกับภาษีเต็มรูป | ลูกค้าขอ อ้างอิงบิลเดิม | รันแยกต่อสาขา |
| ใบลดหนี้ | คืนสินค้า | รันแยกต่อสาขา |
| ใบยกเลิก | void บิล | อ้างอิงเลขบิลเดิม |
| X / Z report | ระหว่างกะ / ปิดกะ | Z report รันต่อเครื่อง |

**เนื้อหาใบกำกับภาษีอย่างย่อ:** ชื่อร้าน เลขประจำตัวผู้เสียภาษี สาขาที่ออก (สำนักงานใหญ่หรือเลขสาขา) หมายเลขเครื่อง POS เลขที่เอกสาร วันเวลา รายการสินค้า ราคา ส่วนลด ยอดรวม VAT (ระบุว่ารวม VAT) ช่องทางชำระ เงินทอน ชื่อแคชเชียร์ และแต้มสมาชิก (ถ้ามี)

**เนื้อหาใบกำกับภาษีเต็มรูปเพิ่มเติม:** ชื่อ ที่อยู่ เลขผู้เสียภาษี และสาขาของผู้ซื้อ แยกมูลค่าสินค้าก่อน VAT และ VAT ชัดเจน

**กฎ**

- เลขเอกสารออกใน transaction เดียวกับการปิดบิล ถ้าปิดบิลไม่สำเร็จ เลขต้องไม่ถูกใช้
- พิมพ์ซ้ำได้ไม่จำกัด สำเนาพิมพ์คำว่า "สำเนา" และนับจำนวนครั้งไว้
- ระบบเก็บใบเสร็จทุกใบเป็นข้อมูลที่พร้อมพิมพ์ซ้ำ ไม่ต้องสร้างใหม่จากข้อมูลปัจจุบัน
- การใช้ POS ออกใบกำกับภาษีอย่างย่อต้องขออนุมัติเครื่องจากกรมสรรพากรก่อน รายละเอียดเนื้อหาเอกสารควรยืนยันกับนักบัญชี

## รายงาน

รายงานทุกตัวกรองตามช่วงวันที่ เครื่อง POS แคชเชียร์ และหมวดสินค้าได้ และส่งออกเป็น Excel หรือ PDF ได้ ยอดขายนับจากบิลที่ปิดแล้ว หักยกเลิกและคืนสินค้า

| รายงาน | สิ่งที่แสดง | ผู้ใช้หลัก |
| --- | --- | --- |
| สรุปยอดขายรายวัน | ยอดขาย ส่วนลด VAT จำนวนบิล ค่าเฉลี่ยต่อบิล แยกตามช่องทางชำระ | ผู้จัดการ เจ้าของ |
| ยอดขายตามช่วงเวลา | ยอดขายรายชั่วโมงและวันในสัปดาห์ สำหรับจัดคนเข้ากะ | ผู้จัดการ |
| สินค้าขายดี / ขายไม่ออก | จำนวนและยอดขายต่อ SKU สินค้าที่ไม่มีการขายในช่วงที่กำหนด | ผู้จัดการ |
| กำไรขั้นต้น | ยอดขาย ต้นทุน กำไร % ต่อ SKU และหมวด | เจ้าของ |
| กะและเงินสด | Z report ย้อนหลัง ผลต่างเงินสดรายกะและรายแคชเชียร์ | ผู้จัดการ |
| ยกเลิก คืน ส่วนลด manual | รายการทั้งหมดพร้อมเหตุผล ผู้ทำ และผู้อนุมัติ | เจ้าของ |
| สต็อกคงเหลือและมูลค่า | จำนวนและมูลค่าตามต้นทุน ณ วันที่เลือก | ผู้จัดการ เจ้าของ |
| ความเคลื่อนไหวสต็อก | ledger ต่อ SKU รับ ขาย ปรับ ตรวจนับ | ผู้จัดการ |
| สินค้าใกล้หมด | SKU ที่ต่ำกว่าจุดสั่งซื้อซ้ำ | ผู้จัดการ |
| รายงานภาษีขาย | ใบกำกับภาษีทุกใบรายเดือน สำหรับยื่น ภ.พ.30 | เจ้าของ นักบัญชี |
| สมาชิกและโปรโมชัน | ยอดซื้อของสมาชิก แต้มคงค้าง ยอดใช้และต้นทุนของแต่ละโปรโมชัน | เจ้าของ |

**หน้าแรกของหลังร้าน (dashboard)** แสดงยอดขายวันนี้เทียบเมื่อวานและสัปดาห์ก่อน กะที่เปิดอยู่ สินค้าใกล้หมด และรายการที่รออนุมัติ

## ข้อมูลหลัก (entities)

ข้อมูลแบ่งเป็น 4 กลุ่ม ได้แก่ ข้อมูลตั้งต้นที่หลังร้านดูแล, เอกสารการขายที่เพิ่มอย่างเดียว, ledger ที่เป็นที่มาของยอดคงเหลือ และข้อมูลควบคุม

| Entity | ข้อมูลสำคัญ | เชื่อมกับ |
| --- | --- | --- |
| **ข้อมูลตั้งต้น** |  |  |

| เครื่อง POS (terminal) | รหัสเครื่อง เลขอนุมัติจากสรรพากร ชุดเลขเอกสาร | กะ บิล อุปกรณ์ |
| ผู้ใช้ / บทบาท | รหัสพนักงาน PIN บทบาท สิทธิ์ | กะ บิล audit log |
| หมวดหมู่ / สินค้า / SKU | ชื่อ ตัวเลือก ประเภทภาษี สถานะ | บาร์โค้ด ราคา รายการขาย |
| บาร์โค้ด / หน่วยขาย | รหัส หน่วย ตัวคูณเป็นหน่วยฐาน | SKU |

| สมาชิก | เบอร์โทร ชื่อ ระดับ ข้อมูลภาษี ความยินยอม PDPA | บิล ledger แต้ม |

| บิลขาย | เลขเอกสาร วันทำการ สถานะ ยอดรวม ส่วนลด VAT | กะ สมาชิก รายการขาย การชำระ |
| รายการขาย | snapshot ชื่อ ราคา ต้นทุน VAT ส่วนลด และโปรที่ใช้ | บิลขาย SKU |

## กฎทางธุรกิจ audit log และความปลอดภัยข้อมูล

เอกสารที่ปิดแล้วแก้ไม่ได้ ทุกการกระทำที่กระทบเงิน สต็อก หรือราคา ถูกบันทึกว่าใครทำ เมื่อไร ที่เครื่องไหน และใครอนุมัติ

**กฎกลางของระบบ**

- บิล ใบลดหนี้ รายการสต็อก และรายการแต้ม เป็นแบบเพิ่มอย่างเดียว ไม่แก้ ไม่ลบ
- รายการขายเก็บ snapshot ของชื่อสินค้า ราคา ต้นทุน VAT และโปรโมชัน ณ เวลาขาย
- การปิดบิล ตัดสต็อก ออกเลขเอกสาร และบันทึกแต้ม สำเร็จพร้อมกันทั้งหมดหรือไม่สำเร็จเลย
- เงินคำนวณเป็นทศนิยมแบบตายตัว ไม่ใช้ floating point และปัดเศษที่ระดับบิลตามกฎเดียวกันทั้งระบบ
- เวลาทุกเครื่องอ้างอิงนาฬิกาของเซิร์ฟเวอร์ ไม่ใช้นาฬิกาของเครื่อง POS
- วันทำการ (business date) แยกจากวันตามปฏิทิน เพื่อรองรับร้านที่ปิดหลังเที่ยงคืน

**Audit log บันทึกอย่างน้อย:** การเข้าและออกระบบ ส่วนลด manual แก้ราคาหน้าร้าน ลบรายการก่อนปิดบิล ยกเลิกบิล คืนสินค้า เปิดลิ้นชักโดยไม่มีการขาย เงินเข้าออก ผลต่างปิดกะ ปรับสต็อก เปลี่ยนราคาหรือต้นทุน เปลี่ยนสิทธิ์ผู้ใช้ และเปลี่ยนการตั้งค่าร้าน

**ความปลอดภัย**

- POS ออกจากระบบอัตโนมัติเมื่อไม่ได้ใช้งานตามเวลาที่ตั้ง แคชเชียร์สลับคนได้โดยไม่ต้องปิดกะ แต่ทุกบิลผูกกับคนที่ทำจริง
- PIN และรหัสผ่านเก็บแบบ hash ล็อกบัญชีเมื่อกรอกผิดหลายครั้ง
- ระบบไม่เก็บเลขบัตรเต็ม เก็บแค่ 4 หลักท้ายและ approval code
- ข้อมูลสมาชิกมีสิทธิ์เข้าถึงจำกัด รองรับคำขอลบหรือแก้ข้อมูลตาม PDPA โดยบิลเดิมยังอยู่แต่ตัดการเชื่อมกับตัวบุคคล
- สำรองข้อมูลอัตโนมัติทุกวัน เก็บย้อนหลังอย่างน้อย 30 วัน และเก็บเอกสารภาษีไว้ตามระยะที่กฎหมายกำหนด (โดยทั่วไป 5 ปี)

## โมดูลเสริมในอนาคต

ระบบหลักขายได้ครบโดยไม่มีอุปกรณ์ฮาร์ดแวร์ เมื่อเพิ่มอุปกรณ์ภายหลัง จะเสียบเข้ามาผ่านจุดเชื่อมที่กำหนดไว้ตั้งแต่ตอนนี้ โดยไม่ต้องแก้ flow การขาย

| อุปกรณ์ | เฟสแรก (ไม่มีอุปกรณ์) | เมื่อเพิ่มโมดูล | จุดเชื่อม |
| --- | --- | --- | --- |
| เครื่องพิมพ์ใบเสร็จ | แสดงใบเสร็จบนจอ หรือพิมพ์ผ่านเครื่องพิมพ์ทั่วไป | พิมพ์อัตโนมัติเมื่อปิดบิล ปิดกะ หรือพิมพ์ซ้ำ | event ปิดบิล ปิดกะ และคำสั่งพิมพ์ซ้ำ |
| ลิ้นชักเงิน | เปิดด้วยกุญแจ ระบบบันทึกเหตุการณ์ | เปิดอัตโนมัติเมื่อรับเงินสด เปิด no-sale ด้วยสิทธิ์ | event รับเงินสด และคำสั่งเปิดลิ้นชัก |
| เครื่องรูดบัตร | รูดเครื่อง EDC แยก แล้วกรอก approval code | ส่งยอดไปเครื่องและรับผลอนุมัติกลับอัตโนมัติ | ช่องทางชำระ "บัตร" |
| เครื่องสแกนบาร์โค้ด | ใช้แบบ USB ที่ทำงานเหมือนคีย์บอร์ด ใช้ได้ตั้งแต่วันแรก | – | ช่องค้นหาสินค้า |
| จอแสดงผลฝั่งลูกค้า | – | แสดงรายการ ยอดรวม และ QR ชำระเงิน | event ตะกร้าเปลี่ยน และ event ขอชำระเงิน |
| เครื่องชั่ง | กรอกน้ำหนักเอง | อ่านน้ำหนักอัตโนมัติ | SKU ชั่งน้ำหนัก |

**สิ่งที่ต้องเตรียมไว้ตั้งแต่เฟสแรก**

- ใบเสร็จเก็บเป็นข้อมูลกลางที่ไม่ผูกกับรูปแบบการพิมพ์
- ตั้งค่าอุปกรณ์รายเครื่อง POS ได้จากหลังร้าน (ประเภท การเชื่อมต่อ เปิดหรือปิด)
- คิวงานพิมพ์ที่บันทึกสถานะ สำเร็จหรือล้มเหลว เพื่อสั่งพิมพ์ใหม่ได้
- บันทึกเหตุการณ์เปิดลิ้นชักไว้เสมอ แม้ยังไม่มีลิ้นชักไฟฟ้า
